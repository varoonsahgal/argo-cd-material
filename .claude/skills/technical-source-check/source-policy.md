# Source Policy

## Preferred source order
1. Official Argo CD documentation (argo-cd.readthedocs.io) and the `argoproj/argo-cd` GitHub repository (releases, changelog, issues for known behavior changes)
2. Official Kubernetes documentation
3. Official Helm and Terraform (and relevant provider) documentation
4. Other official CNCF/Argo-ecosystem project pages (e.g., Argo Workflows docs, only for the comparison the outline calls for)
5. Secondary sources (blog posts, conference talks) only when primary sources do not answer the question

## Avoid
- Treating an old tutorial or blog post as current CLI/UI guidance
- Presenting a feature available only in a newer (or older) Argo CD release as universally current without noting the version
- Generalizing one team's configuration or one incident into a universal best practice
- Presenting social-media claims as established technical facts

## Courseware note
Current-source checks should improve accuracy without cluttering instructional material. Keep citations/source notes in instructor notes or review artifacts when inline sourcing would distract from the guide. Screenshots follow their own attribution rule — see the `screenshot-capture` skill.
